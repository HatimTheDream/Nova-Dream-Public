# Publication Continuation For Release Operators

A blocked full publication can resume through a separately qualified operator revision while retaining the original application candidate, signed assets, completed CI, packaging and recovery evidence. This does not start a new release or reset any original deadline.

The configured release entrypoint provides these commands:

1. `npm run release:deliver -- plan-publication-continuation JOURNAL OPERATION_ID REQUEST`
2. `npm run release:deliver -- reconcile-publication JOURNAL OPERATION_ID EXECUTION_REQUEST`
3. `npm run release:deliver -- resume JOURNAL OPERATION_ID`

The plan verifies current prerequisites and performs an actual read-only host staging plan. Its immutable reference needs independent review and a separate execution intent, both bound by the execution request. Grant creation remains behind the configured storage runner and deployment lock. The first resumed invocation records its storage admission only after all native session, source, capacity and freshness checks; later observations use that grant-specific admission.

Admission is limited to an expired, open full-release operation with ten completed prerequisite phases, all seven completed package substeps, an existing publication reservation, and no installation or acceptance reservation. Exact original keys, inputs, observations, owner closure and history remain bound. Unknown effects, changed evidence or active owners refuse continuation. The finite grant cannot renew itself.

An expired browser preparation requires genuine failure and closure evidence before a distinct linked session can be created. Original records remain unchanged. The successor retains the release operation and target, with its own directory, service unit and bounded clock. Existing worker, saved-reply, reload and single-message acceptance checks remain in force.

The transfer route uses the explicitly qualified GNU timeout for both host identity admission and actual nonroot exclusive uploads. It preserves finite bounds, process cleanup and uncertain-upload reconciliation without changing system-wide command selection.

Separate operator revisions must be clean, published independently in both repositories and pass their exact operator CI. Completed application evidence remains reusable only for unchanged immutable inputs. Final installation, saved-work/account/health checks, one saved Assistant reply, browser reload acceptance and storage closeout remain required. This route does not establish a general fast-release timing guarantee.
