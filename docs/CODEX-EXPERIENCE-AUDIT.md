# Assistant experience: Codex reference audit

Reviewed 22 September 2026 against the **1.9.8 UI / build 1.0.196**, carried forward through **1.9.9 request efficiency** and **1.9.11 header and docked navigation** into the local **1.9.13 compact-navigation candidate**; earlier evidence is retained below. Both independent 1.9.13 candidates passed their local full quality gates and exact artifact comparison. Source publication and hosted acceptance are recorded separately; the last live version observed during this audit was **1.9.6**. This is a reference and source audit, not a declaration of full parity or live deployment.

## Evidence and limits

The initial supplied screenshots show elapsed-time disclosures, commentary interleaved with quiet action summaries and a final answer outside completed work. Fresh native screenshots now also record the actual installed desktop application's menus, retained work, search, questions, file viewers, subagents, settings and review. A controlled synthetic task additionally exercised question completion, steering, queue editing/deletion/consumption, Stop, ordinary message editing, document attachment readback and a generated Word revision with verified download. Its About dialog reports version **26.915.31945**, released 17 September 2026. Unobserved states below remain explicit gaps rather than being inferred from documentation.

**Mode provenance matters.** The installed application exposes distinct **ChatGPT and Codex application modes**. Within ChatGPT mode, **Chat and Work are separate draft/task choices**: the inspected Chat draft uses a compact Instant response control and omits the Work access/effort controls. A local project is explicitly unavailable for that Chat draft. Switching the application to Codex mode exposes a changed-files summary beneath the same completed answer and a Review side tab. The initial file viewers and question reopening were observed in ChatGPT mode. Shell details, Last Turn review and the controlled question, queue, Stop, edit and attachment outcomes were observed in Codex mode. Do not conflate a Chat/Work choice with the application mode or assume every interaction behaves identically across them.

Official desktop documentation and rendered examples remain supplementary references. Desktop, web, CLI, IDE and application modes must not be conflated. Documentation illustrations are not fresh captures of the installed app. Native screenshots and identifying content are private QA evidence and are not distributed with this document.

Nova source was traced across its composer, transcript, stored history, runtime, files, side panels, queue, approvals, questions, teams and recovery. Initial component fixtures used synthetic conversations and a placeholder composer at 1200px, 390px and 320px. A later verification pass inspected the full production-built Nova app and services with a controlled synthetic Assistant runtime, including the actual composer, queue and request receipts. Neither pass is an installed-app or live-provider acceptance test. Native reference inspection is a separate evidence set: its completed outcomes do not establish Nova behavior, microphone operation, physical-phone acceptance or deployment. The walkthrough remains incomplete.

**Green** means the scoped design/implementation should be retained; it is not blanket end-to-end certification. **Orange** means a specific improvement or acceptance gap remains. **Red** means a named expected workflow is missing or reaches a dead end. No aggregate parity percentage is assigned.

## Reference principles

1. Make the response the primary content. Keep ordinary commentary readable, and activity smaller and quieter. Use a small icon and verb. Respect the mode distinction: inspected ChatGPT-mode rows were plain, while Codex-mode command disclosure combined command and output in a bounded Shell panel. The Nova candidate now uses one shared Shell surface, verified locally with exact saved command/result text and Copy. This is a scoped design match, not complete behavior parity.
2. Treat a reply as one work phase. Show elapsed time while working; keep its completed duration fixed. Collapse finished activity and leave the answer visible. Never infer success from elapsed time or connection silence, and do not reproduce the reference's observed stopped-duration anomaly.
3. Group only related actions. Compact summaries such as “Read files, ran commands” should expand to exact individual actions. Keep approvals, failures and user decisions discoverable. Do not combine unrelated runs merely because their labels match.
4. Keep one compact composer. Place the few useful controls near the writing; reveal extra settings through contextual menus. Keep pending follow-ups shallow and close to the composer, with secondary actions in overflow. Preserve Nova's simple effort slider rather than adding a larger settings hierarchy.
5. Keep context beside the task. Actual Markdown, PDF and Office viewers in ChatGPT mode and the Review pane in Codex mode retain the conversation beside the result. Nova must also preserve its draft and exact result identity through that navigation. Keep viewer support separate from ingestion, editing and annotation acceptance. [Files](https://learn.chatgpt.com/docs/artifacts-viewer), [code review](https://learn.chatgpt.com/docs/code-review?surface=app).
6. Make navigation preserve work. The native ChatGPT-mode pass directly shows global search, current-chat Find, exact-match navigation and a clear no-match state. The Chat/Work draft switch retains unsent text and exposes a mode-specific project constraint; broader project-selection outcomes remain unverified. [Projects](https://learn.chatgpt.com/docs/projects?surface=app), [commands](https://learn.chatgpt.com/docs/reference/commands).
7. Show real delegation. Native ChatGPT-mode captures show named Active/Done agents and a retained child conversation beside its parent. Nova's sequential Team Work is a different capability and should be described accurately. [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents).

Nova should retain its warm palette, lynx, rounded primary controls, Chat/Work distinction and chosen startup experience. Quiet transcript disclosures do not need the raised styling used for primary application actions.
